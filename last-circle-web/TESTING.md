## 온라인 동기화

- 80/180/300ms 지연·지터·중복/재전송·뒤바뀐 응답에서 미확인 입력만 재적용하고 같은 입력으로 이동·사격을 두 번 실행하지 않습니다. 과속 입력/잘못된 순서를 거부하며 길어진 연결 단절은 epoch를 바꾸어 복구합니다.
- 실제 SQLite에 20명이 동시에 각자의 입력 행을 써도 방 전체 저장은 조정기 한 번의 처리로 끝납니다. 다른 처리기의 임대권·오래된 seq·다른 epoch·비인증 요청 거부와 HTTP 대체 응답의 본인 인벤토리 보존을 확인합니다.
- 방 상태/입력 조회와 조건부 저장/공개 상태 반영을 각각 D1 배치로 묶습니다. 동시에 20개 시청자가 조회해도 한 번만 읽고 같은 처리기의 연결에 상태를 나누어 전달하는지 검사합니다. 다른 요청이 먼저 방을 갱신하면 CAS가 실패하고 해당 체크포인트가 공유 DB 상태를 덮어쓰지 않는지도 검사합니다. 메모리의 진행 중 상태 전송은 체크포인트 기록과 분리합니다.
- 진행 중 방은 임대권 아래 메모리에서 계산하고 저장/다른 처리기의 입력 조회를 비동기로 수행합니다. 인위적인 500ms 저장 지연 중에도 350ms 이내에 새 이동을 전송하고 이탈 전에 해당 입력을 체크포인트에 남기는지 검사합니다. 다른 처리기에서 온 이탈이 최신 생존자의 명령과 떠나는 사람의 현재 장비를 보존하며 두 번 드롭하지 않는지, 배열/가방을 수정해도 이전 스냅샷을 바꾸지 않아 탄약 델타가 누락되지 않는지도 검사합니다.
- 인증된 SSE가 입력 응답과 독립적으로 상태를 보내고 다른 사람의 토큰/비공개 가방·퀘스트를 노출하지 않는지 검사합니다. 오래된 공개 상태가 최신 버전을 덮어쓰지 못하며 델타 병합이 본인 정보를 보존합니다. 사격 과거 위치 보정은 최대 400ms입니다.
- 실제 HTTP를 쓰는 두 Chromium 문맥을 1:1 매칭·양쪽 준비·경기로 연결했습니다. 입력 요청 왕복에 140~170ms를 넣고, 입력 응답 하나는 약 1,045ms 늦게 돌려주었습니다. 상대의 첫 이동은 약 **175ms**에 보였고, 해당 느린 응답을 기다리지 않고 SSE로 도착했습니다. 수신 상태 나이 중앙값 25ms·95백분위 43ms였습니다. 이 값은 로컬 합성 지연 실험이며 실제 인터넷의 지연 보장이 아닙니다.
- 74개 전진 샘플의 최대 뒤쪽 보정 0m, 서버 전체 사격/로컬 총성/예측 키 각각 **23개**, 상대 서버 보행 위상과 렌더 위상 각각 9.7552, 브라우저 오류 `[]`였습니다. 스트림의 짧은 최근 사격 목록과 서버 전체 사격 기록을 구분해 비교합니다.
- 위 네트워크 실험은 두 SwiftShader 화면의 소프트웨어 GPU 정체를 분리하려고 GPU 그리기만 중지했습니다. 실제 입력·조정기·SSE·예측·캐릭터 포즈·음향은 실행합니다. 별도 화면 검사는 렌더링을 실행합니다. 위치/시간 픽스처는 로컬 전용 검사 방에서만 적용합니다.

- 요청을 1초에 5·20·100개 보냈을 때 모두 세계 시간이 정확히 1초/25틱 진행합니다. 자신의 예측 보행과 서버의 거리 기반 보행 위상, 상대 위치/회전·보행 보간을 검사합니다.

- 화상은 불구역 밖에서도 유지되며 1초마다 정확히 5 HP를 깎습니다. 접촉 전염, 벽/층 차폐, 강에 몸을 담가 소화, 젖은 동안 재점화 방지를 검사합니다.
- 4종 투척물의 낮고 약한 짧은 투척·세기별 거리·예측과 실제 일치·바닥 마찰·완전 정지를 검사합니다. 기존 폭발 한 번·연막/섬광·유한한 수량도 유지합니다.

## 브라우저와 성능

실제 HTTP를 사용하는 두 Chromium 문맥을 1:1로 매칭·준비·시작하고 요청에 왕복 140~170ms 지연을 넣었습니다. 75개 이동 샘플에서 최대 역방향 보정 0m, 서버 사격/로컬 총성/예측 키는 각각 20개, 상대의 보행 위상과 렌더링 위상은 모두 9.7552, 오류 배열 `[]`였습니다. 이 동기화 검사에서는 소프트웨어 GPU의 두 화면 렌더링 정체를 분리하기 위해 GPU 그리기만 중지하고 실제 앱 입력·폴링·예측·캐릭터 포즈 갱신·오디오를 실행했습니다. 별도 PC·터치 장면에서는 GPU 렌더링을 실행해 화면과 입력을 확인했습니다.

로컬 Chromium PC에서 실제 렌더링·1인칭 총/손·화상 화면·버튼을 놓을 때 한 번 투척·차량 탑승/내리기를 확인했습니다. 844×390 터치에서는 실제 터치 입력으로 사격 버튼 누르기 → 65px 아래로 드래그해 세기 낮추기 → 놓아서 한 개 소모를 확인했고 오류 배열은 `[]`입니다. QA용 상태 접근 코드는 별도 임시 번들에만 넣으며 배포 빌드에는 포함하지 않습니다.

20명 AI의 첫 120초/3,000틱을 같은 초기 시드와 투하 지연으로 계산한 로컬 CPU 비교에서, 0.6.0은 약 24.16초, 경로 최적화를 적용한 0.7.0은 약 3.99초였습니다. 이전/신규 맵과 이동 변화로 AI 경로 자체도 달라지므로 순수 알고리즘 단독 비교나 FPS 보장은 아닙니다. 실제 기기에서는 GPU·화질·발열·네트워크에 따라 성능이 달라집니다. 이 측정 이후 무거운 경로 탐색 예산을 틱당 2회에서 1회로 분산했습니다.

실제 iOS/Safari·Android 하드웨어, 20대 실기기 장시간 접속, 물리 스피커 음질은 미검증입니다. 60Hz 입력 예측·25Hz 세계 처리·HTTP/D1 동기화를 사용하며 모든 인터넷 지연을 없애는 것은 아닙니다.
